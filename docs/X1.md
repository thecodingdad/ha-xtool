# xTool X1 (experimental read-only)

X1 uses the genuine `JS001` / platform `2.0` profile (`JS001_V2`), not the M2
(`JS002`) protocol. Other models keep their existing transports and behavior.

## Available observations

- Raw reported `mode`, `moveState` and `gohomeState`. Missing values are unknown;
  failed refreshes make entities unavailable. These are not safety assertions.
- Onboard accessory-slot connectivity, reported status and application firmware.
- Dongle-connected Bluetooth inventory (`M9098`): a count and reported type
  prefixes, without peripheral addresses. A missing/offline dongle means unknown,
  not zero. An empty list is not proof that an AP2 is physically absent.
- On-demand far, near and side JPEG snapshots, verified on hardware through Home
  Assistant. Transfers are checked before an image is returned; images are not
  persisted by the integration. These are **snapshots, not live video**.

AP2 telemetry is **not verified or exposed**. No scan, pairing, accessory controls,
job/motion commands, lighting, firmware updates or linked power control are added.
The minimum polling interval is 60 seconds.

## Setup

1. Add the X1 through the normal integration flow, or select **xTool X1
   (experimental read-only)** when entering its IPv4 address manually.
2. Open the entry's **Configure → Grant** option and import an existing,
   owner-authorized grant issued for this integration. This implementation does
   not obtain grants or perform pairing. Without a grant, only advertised
   identity and discovery reachability are available.
3. The JSON fields are `host`, `serial`, `client_id`, `consumer`, `leaf_sha256`,
   `user_id`, `timezone` and `token`. Preserve the supplied values, including the
   canonical client UUID and original certificate pin. Do not substitute Studio
   or cloud credentials.

The masked import stores the grant privately in Home Assistant's `.storage`, not
in entry options. Protect storage and backups as credentials. Connections require
that exact leaf certificate pin, not manufacturer-CA authentication. Refused auth,
a changed device identity or pin, or a missing configured grant fails closed;
there is no tokenless fallback or automatic trust refresh.

## Tests

With Home Assistant and its camera dependency installed (tested on 2026.11.1):

```sh
python -m unittest discover -s tests -v
```

The suite uses synthetic identifiers, generated JPEGs and a loopback TLS peer. It
covers discovery/model isolation, grant storage, HA entity states, read-only
requests, authentication failures and corrupt/incomplete snapshot transfers.
